# 时隙容量

时间节点为0到H，移动从t到t+duration，开放段为半开[a,b)，整条移动区间[t,t+duration)必须被开放段覆盖，抵达b合法。容量按出发时隙给定，不等于车辆在途总数。waiting_capacity[t]限制等待[t,t+1)的人，瞬时通过不占该等待边，但仍受其他边容量限制。

releases只能进入其声明时刻，未安排人员留在源侧不算转移。安置入口按实际到达时刻，所有时刻再共用total_capacity；安置节点没有外出道路，正式接收不再等待。每候选时域独立限制移动到达<=H。整数流路径需要保留每条道路ID，平行道路不合并来源。最大流割以原容量求和，独立重放只读原数据。

现有domain只检查原始字段，不建时空图、求流或排路。

## 离散时间容量分析（response_data.model / flow / enumerate）

`model.validate`在原始字段之上做完整建模校验，返回索引化`Model`；`flow.analyze`对`deadlines`中每个候选截止时刻H，在只含0..H层的时间展开图上求整数最大流，回答“截至H最多已安置多少人”。

### 图构造口径

* 时间节点为(n,t)；源点边只在release声明时刻建立，容量为当次释放人数，未注入人员留在源侧。
* 等待边(n,t)->(n,t+1)容量为waiting_capacity[t]，语义即占用[t,t+1)；安置节点不建等待边。
* 道路边(u,t)->(v,t+duration)仅当存在开放段[a,b)满足a<=t且t+duration<=b时建立，容量取该道路capacity[t]。抵达恰等于b合法；b之后出发无对应边。
* 安置点s在t的入口边(n,t)->中间点容量为entry_capacity[t]；中间点再经唯一一条容量total_capacity的边到汇点。该总容量边跨所有时刻共享，同一总名额不会逐时隙复用。
* 只建到达时刻<=H的边；逐层增量扩展时更早截止的结果不含任何未来边。

### 证据与可复算性

每个候选H输出max_housed、cut_value（断言二者相等）、带时间节点下标的割边与业务ref、全部正流量边、整数路径批次，以及`replay_flow`只读原始道路/开放/等待/接收容量的独立重放结果（含逐资源峰值占用与时间节点守恒核对）。批次保留每段道路ID、出发与抵达时刻、等待区间和安置入口时刻。

最早清空时间取首个max_housed==总释放人数的候选H，其成立建立在全部更早候选均未清空（各自附割证据）的基础上。最大候选H仍未清空时报告`not_cleared_within_horizon`，只陈述给定时域结论，不断言现实永久不可行。

### 预算、枚举与离线边界

时间节点预算取`max_time_nodes`，可选`max_edges`约束边数；扩展下一层会超预算时保留已完成层结论，后续候选标记`not_attempted`，整体状态为`budget_exceeded`。

`enumerate.brute_force`是与最大流完全独立的小规模核对：先在(节点,时刻)状态空间枚举所有合法时序路径，再做逐资源容量约束的整数分配搜索，路径数或分支超预算时返回下界并标记未完成。重放与枚举都不读取求解器内部图。本工具仅用于冻结演练方案的离线推演，不向真实人员或交通设施下达指令。
